# 全球农业/食品/植物/作物 PhD 导师与申请数据库

公开静态页面，收录农业、食品、植物、作物方向的博士导师和申请入口。线上地址为 [https://521-zjw.github.io/phd-advisors/](https://521-zjw.github.io/phd-advisors/)。不需要登录。

当前首版：10 个国家、157 位导师、35 个申请项目、1 条更新日志。其中 36 位标为高匹配。页面上的数字以 JSON 为准，会随每日更新变化。

## 本地打开

页面用 `fetch` 读取 JSON，直接双击 `index.html` 时浏览器会拦截。在仓库根目录启动一个本地服务：

```bash
python3 -m http.server 8000
```

然后打开 [http://127.0.0.1:8000/](http://127.0.0.1:8000/)。

## 更新规则

每日更新只做两件事：追加新记录，或在已有记录上刷新字段。

- 不删除 `data/records.json` 里的导师记录。
- 不删除 `data/log.json` 里的日志行。
- 不删除 `data/programs.json` 里的项目键。已有导师的 `id` 一旦写上就不再改、不再复用，也不要为同一人再追加一条新 id。
- 截止日期过了，不要删数据，也不要为了“过期”而清空 `dd` 或 `add`。页面按打开当天的本地日期自动显示「已截止」。截止日当天仍算开放，次日才变成已截止。

`最近一次更新` 取 `data/log.json` 数组的最后一条。页面把日志倒序显示，所以新日志必须追加在数组末尾。

## 每天怎么改

1. 新导师：在 `data/records.json` 数组末尾追加一个对象。不要插入到中间，也不要重排已有记录，这样默认排序和 diff 都保持稳定。
2. 已有导师：只改这一条里的字段，例如职称 `t`、研究方向 `r`、主页 `h`、最后核实日期 `v`。留在原位置，保留 `id`。
3. 新的申请项目：在 `data/programs.json` 里增加一个新键。改截止说明时，改项目的 `d` 和 `dd`，不要把同一句话抄进每一位导师。
4. 某一位导师有单独的在招广告：在该记录上写 `ad`（广告 URL），需要时再写 `add`（广告截止日期）。这会优先于所属项目的截止日期。
5. 要手动标状态：写 `x`，例如 `"已截止"`。一旦有 `x`，页面直接显示这句话，并且不把它算作开放申请。
6. 每次更新都在 `data/log.json` 末尾追加一条，不要改掉或删掉旧日志。
7. 保存为无 BOM 的 UTF-8，然后运行 `node scripts/validate.mjs`。通过后再提交。

新增导师的形状如下。这是格式示例，不要原样写入数据文件。

```json
{
  "id": "xx-example",
  "n": "Example Name",
  "t": "Assistant Professor",
  "r": "研究方向",
  "i": "Example University",
  "d": "Example Department",
  "c": "美国",
  "k": "PC",
  "h": "https://example.edu/people/example",
  "p": "UMD",
  "f": false,
  "a": "2026-11-11",
  "v": "2026-11-11"
}
```

有单独岗位广告时可以多写两个字段：

```json
{
  "ad": "https://example.edu/jobs/phd-2026",
  "add": "2026-12-15"
}
```

新日志：

```json
{
  "date": "2026-11-11",
  "title": "新增导师",
  "detail": "追加 1 位，并刷新 2 条截止日期。"
}
```

## 目录

| 路径 | 作用 |
| --- | --- |
| `index.html` | 页面入口，放在仓库根目录，供 GitHub Pages 使用 |
| `assets/styles.css`、`assets/app.js` | 样式和交互，没有第三方依赖 |
| `data/programs.json` | 申请项目，对象，键是项目 id |
| `data/records.json` | 导师，数组，一位一条 |

| `scripts/validate.mjs` | 检查 JSON 结构和 id 是否唯一 |

## 字段

三个文件都使用下面这些短字段名。不要改成 `name`、`title` 这类长名字。

### `data/programs.json`

键是项目 id，例如 `UMD`、`KSU_GFS`。id 使用大写字母、数字和下划线。

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `n` | 是 | 名称 |
| `u` | 是 | 申请入口 URL |
| `l` | 是 | 语言要求。官方页面没写就填「未明确」 |
| `g` | 是 | GPA 要求。没写就填「未明确」 |
| `d` | 是 | 截止说明，给人读的原话。没写就填「未公布」 |
| `dd` | 否 | 截止日期，`YYYY-MM-DD`。早于打开页面的本地日期时，页面显示「已截止」 |
| `o` | 是 | `cycle` 按轮次招生，`jobs` 岗位制（看招聘页），`rolling` 滚动，`none` 未公布 |
| `s` | 是 | 这条申请要求的来源 URL |

### `data/records.json`

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `id` | 是 | 唯一键。小写字母、数字和连字符，如 `us-tiwari`。全文件不可重复 |
| `n` | 是 | 姓名 |
| `t` | 是 | 职称 |
| `r` | 是 | 研究方向 |
| `i` | 是 | 学校或研究所 |
| `d` | 是 | 院系。和项目里的 `d`（截止说明）不是一回事 |
| `c` | 是 | 国家。新国家可以直接写，页面会跟着出现 |
| `k` | 是 | 类别字母，可组合、不重复：`A` 农业，`F` 食品，`P` 植物，`C` 作物。例如 `PC` 会显示为「植物、作物」，两个类别筛选都能命中 |
| `h` | 是 | 导师主页 URL |
| `p` | 是 | 项目 id，必须是 `programs.json` 里的键 |
| `f` | 是 | 高匹配。JSON 布尔值 `true` 或 `false`，不要写成字符串 |
| `a` | 是 | 首次收录日期，`YYYY-MM-DD` |
| `v` | 是 | 最后核实日期，`YYYY-MM-DD` |
| `s` | 否 | 来源 URL。不写时，页面用来源链接打开主页 |
| `ad` | 否 | 在招岗位广告 URL |
| `add` | 否 | 广告截止日期，`YYYY-MM-DD` |
| `x` | 否 | 手动状态，例如 `"已截止"` |

### `data/log.json`

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `date` | 是 | 日期，`YYYY-MM-DD` |
| `title` | 是 | 标题 |
| `detail` | 是 | 说明 |

## 页面怎么判断在招

对每一位导师，按这个顺序，命中一条就停止：

1. 记录有 `x`：直接显示 `x`，不算开放。
2. 记录有 `ad`：`add` 早于今天则显示「已截止」；没有 `add`，或 `add` 是今天及以后，则显示「有在招岗位」，算开放。
3. 没有对应项目：显示「未公布」。
4. 项目有 `dd`：早于今天显示「已截止」；今天及以后显示「项目开放申请」，算开放。
5. 项目 `o` 为 `jobs`：显示「岗位制·看招聘页」，不算开放。
6. 项目 `o` 为 `rolling`：显示「滚动」，不算开放。
7. 其余显示「未公布」。

「只看有在招/开放申请」只保留上面算作开放的记录。岗位制和滚动招生不会仅仅因为类型就出现在这个筛选里；要出现，需要给该导师写一条还没过期的 `ad`。

申请项目表按 `dd` 从早到晚排列，没有 `dd` 的排在最后。已经过去的日期仍排在前面，状态写成「已截止」。导师表的「按截止日期」则是另一套顺序：还没过期且有日期的在前，没有日期的居中，已过期的在后。

比较用的是 `YYYY-MM-DD` 字符串和打开页面的人的本地日期。

## 校验

```bash
node scripts/validate.mjs
```

脚本检查三份 JSON 能否解析、有没有重复键、字段是否符合上面的结构、日期和 URL 是否合法、导师 `id` 是否唯一，以及 `p` 是否指向现有项目。它不联网，也不会修改文件。失败时退出码为 1。

## GitHub Pages

站点从 `main` 分支的根目录发布。仓库里已经放了根目录的 `index.html` 和 `.nojekyll`。

这还不够自动打开 Pages。需要在 GitHub 仓库里手动开启一次：

**Settings → Pages → Build and deployment → Deploy from a branch → Branch: `main`，Folder: `/ (root)` → Save。**

保存之后，页面会出现在 [https://521-zjw.github.io/phd-advisors/](https://521-zjw.github.io/phd-advisors/)。只把文件推到 `main`，不会自己打开这个开关。
